# M-pilot 결과 — 다모듈 증분 개발 (exprkit)

> 설계: [../benchmark/MIDSCALE_DESIGN.md](../benchmark/MIDSCALE_DESIGN.md) B4 항목의 파일럿 · 하네스: oracle.py / score_M.py · 원자료: logs/results_M.json · 로그: logs/run_log.jsonl
> 구성: s-expression 계산기 패키지 `exprkit`(다모듈), 5세션 증분 개발(S0 빌드 → S1 `*`,`/` → S2 `neg` → S3 `pow` → S4 `lt/gt/eq`), 3그룹(B 무기억 / P 노트 / ASK SSOT+ARCHITECTURE 매트릭스) × 2시드 = 30 세션 실행(Haiku, 증분 편집, 디스크 인계).

## 1. 한 줄 결론

**이 파일럿 규모에서는 변별이 일어나지 않았다(천장).** 세 그룹 모두 최종 9/9 연산자 완전 지원, **교차모듈 회귀 0·교차절단 누락 0·import 오류 0**, floor-division 결정도 전 그룹 보존. **유일한 차이는 비용**: ASK가 baseline 대비 **토큰 +60%**. → M-pilot은 ASK 효과를 **입증하지 못했고**, 소규모에서 확인된 **비용 페널티가 이 규모에서도 유지**됨을 확인. (단 이는 crossover 가설의 반증이 아니라, **임계점이 이 파일럿보다 높다**는 신호 — §3.)

## 3. 왜 천장이었나 (진단 — 핵심)

설계가 의도한 메커니즘(연산자가 늘수록 *모든 visitor를 빠짐없이 갱신*해야 하고, 누락 시 교차모듈 회귀)이 **발현되지 않았다.** 원인:

1. **제네릭 디스패치가 교차절단 계약을 무력화.** 대부분의 에이전트(B 포함)가 연산자를 **연산자 레지스트리/제네릭 재귀**로 구현해, 새 연산자 추가가 *한 곳 등록*으로 끝났다. evaluate와 to_rpn이 같은 레지스트리를 제네릭하게 처리 → "visitor 누락" 자체가 구조적으로 불가능. (여러 에이전트가 명시적으로 "제네릭 visitor라 변경 불필요"라고 보고.) **좋은 설계가 계약을 자명하게 만들어, ASK의 명시적 매트릭스가 더할 게 없었다.**
2. **규모가 임계점 아래.** ~5개 작은 모듈·8개 연산자는, 매 세션 전체를 재이해해도 비용·누락 위험이 낮다(B2 소규모 천장과 동형). 재발견 비용 절감이라는 ASK 이득의 표면이 충분히 크지 않다.
3. **floor-div 함정(B5-lite) 미발화.** `/` 결정은 S1에서 전 그룹에 동일 명시됐고 이후 아무도 `/`를 다시 건드리지 않아, 무기억도 보존 → 변별 불가(예상된 약점).

## 4. 정직한 해석

- **ASK 효과 미입증 + 비용 +60% 확인.** 이 파일럿은 "중규모면 ASK가 효과적"을 보여주지 *못했다*. 단발(B1)·가산 소규모(B2)와 같은 패턴(천장 + 비용)이 반복됐다.
- **그러나 crossover 가설의 반증은 아니다.** 이 파일럿은 사실상 "하위-중규모"이며, 제네릭 디스패치로 계약이 자명해져 임계점에 못 미쳤다. 임계점은 이 설계보다 **위**에 있다.
- **하네스·파이프라인은 검증됨**(오라클 자기검증 통과, 음성대조로 누락 검출 확인, 30체인 결정적 채점). 즉 측정 도구는 정상이고, **과제 설계가 변별을 못 만든 것**이 결론.

## 5. 변별을 만들려면 (다음 설계의 필수 수정)

1. **visitor를 제네릭으로 처리할 수 없게 만들 것.** 핵심 결함은 "연산자=레지스트리 한 줄"이었다. 대신:
   - **infix 프린터(연산자별 기호+우선순위)** — 노드마다 다른 렌더링 → 제네릭 불가.
   - **구조가 다른 노드 타입**(예: `if/then/else` 삼항, `let x=… in …` 바인딩, 변수/환경, 람다) — 각 visitor가 노드별로 *다르게* 처리해야 함 → 누락 가능.
2. **규모를 키울 것(L급).** 모듈 15+·세션 10+·코드 수천 LOC라야 재발견 비용 절감(ASK)이 표면화.
3. **결정 충돌 함정을 "재접촉 강제"형으로**(B5): 후반 요구가 초기 결정을 *반드시 다시 건드리게* 설계(예: 우선순위 규칙을 뒤집는 신규 연산자).
4. 통제는 유지(P vs ASK 분량 정합, ≥8 프로젝트, 중·약 모델).

- `python aggregate_M.py` → logs/results_M.json + 콘솔 요약(= logs/aggregate_M_output.txt) 재생성.
- 각 세션 스냅샷(runs/<group>/seed<k>/s0..s4/)·전 호출 로그(logs/run_log.jsonl) 보존. 채점은 oracle.py 대조(결정적).

> 결론: **M-pilot은 ASK 효과를 입증하지 못했다(천장)**. 비용 +60%만 확인. 원인은 규모 부족 + 제네릭 디스패치로 인한 교차절단 계약의 자명화. 유효한 입증을 위해선 §5(비제네릭 visitor·구조적 노드·L급 규모·재접촉형 함정)가 필요하다.

# 1. 프로젝트 기본 정보

## 프로젝트명

습관 트래커 (Habit Tracker)

## 프로젝트 목적

매일 하기로 한 습관을 실제로 했는지 하루 단위로 체크하고, 며칠째 이어오고 있는지를
한 화면에서 바로 확인한다. 기록을 남기는 것보다 **연속(streak)이 끊기는 것을 눈에 보이게** 만드는 것이 목적이다.

## 대상 사용자

개인 1명. 자기 습관을 스스로 관리한다. 계정도 공유도 없다.

## 핵심 가치

앱을 열면 3초 안에 "오늘 뭘 해야 하고, 지금 며칠째인지"를 안다.

## 산출물 작성 언어

한국어

# 2. 프로젝트 설명

브라우저에서 `index.html`을 열면 바로 동작하는 정적 웹페이지 하나. 서버도 빌드도 없다.
습관 목록을 만들고, 오늘 칸을 눌러 체크하고, 최근 2주치 기록을 격자로 본다.
데이터는 브라우저 localStorage에만 저장한다.

혼자 쓰는 도구이므로 로그인, 계정, 서버 동기화는 만들지 않는다.

# 3. 핵심 기능

## MVP에 반드시 포함할 기능

* 기능 1: **습관 추가 / 삭제** — 이름을 입력해 습관을 추가하고, 목록에서 삭제한다.
* 기능 2: **오늘 체크 토글** — 오늘 칸을 눌러 완료/미완료를 전환한다.
* 기능 3: **최근 14일 격자** — 습관별로 최근 14일의 완료 여부를 한 줄 격자로 보여준다.
* 기능 4: **연속 달성(streak) 표시** — 습관별로 오늘 기준 며칠째 연속인지 숫자로 보여준다.

## 후순위 기능

* 기능 1: 습관별 색상 지정
* 기능 2: 주간 달성률 요약
* 기능 3: JSON 내보내기 / 가져오기

# 4. 사용자 시나리오

1. 처음 연다. 습관이 하나도 없으므로 "습관을 추가해 보세요" 안내와 입력창만 보인다.
2. "물 2L 마시기"를 추가한다. 최근 14일 격자가 전부 빈 칸으로 나타난다.
3. 오늘 칸을 누른다. 칸이 채워지고 streak이 `1일`이 된다.
4. 다음 날 다시 연다. 격자가 하루 밀려 있고, 오늘 칸은 비어 있다.
5. 3일 연속 체크하면 streak이 `3일`이 된다.
6. 하루 건너뛰고 다시 체크하면 streak이 `1일`부터 다시 시작한다.

# 10. 횡단(아키텍처) 기준선

## 데이터 모델 공통 규칙

* 날짜는 **로컬 타임존 기준 `YYYY-MM-DD` 문자열**을 키로 쓴다. UTC나 타임스탬프를 키로 쓰지 않는다.
* localStorage는 **단일 키 `habit-tracker.v1`** 하나만 사용하고, 저장 객체는 `schemaVersion` 필드를 가진다.
* 완료 기록은 "완료한 날짜의 집합"으로 저장한다. 미완료를 따로 저장하지 않는다.

## 네이밍 규칙

* JS 변수·함수 camelCase, 파일명 kebab-case, CSS 클래스 kebab-case.

## 상태 관리 계약

* 상태 변경은 항상 **`상태 갱신 → localStorage 저장 → 화면 렌더`** 순서의 단방향으로만 일어난다.
  DOM을 직접 고쳐서 상태와 화면이 따로 놀게 만들지 않는다.

## 입력 검증 (공통)

* 습관 이름은 앞뒤 공백을 제거한 뒤 **1~30자**, 같은 이름 중복 불가.

## ★ 연속 달성(streak) 규칙 — 고정

* **하루라도 건너뛰면 streak은 0으로 리셋한다. 유예(grace day)나 보정은 없다.**
* 이건 이 앱의 핵심 정책이다. "끊긴 걸 눈에 보이게 한다"는 목적이 여기서 나온다.

# 11. 테스트 / QA 요구사항

## 반드시 검증해야 할 핵심 시나리오

* 시나리오 1: 3일 연속 체크 → streak = 3. 하루 건너뛰고 체크 → streak = 1.
* 시나리오 2: 오늘 체크 후 자정을 넘기면, 어제 칸은 채워진 채로 오늘 칸이 새로 비어 있다.
* 시나리오 3: localStorage가 비어 있거나 값이 깨졌을 때(수동 변조 포함) 앱이 죽지 않고 빈 상태로 뜬다.

## 자동 테스트가 필요한 영역

* 데이터 처리: 날짜 키 생성, streak 계산, 저장 데이터 파싱·검증 — 순수 함수 단위 테스트.
* 화면: 자동 테스트 대상 아님. 수동 QA로 확인한다.

## 수동 QA가 필요한 영역

* 화면 사용성: 360px 폭에서 격자·버튼이 겹치지 않는지
* 예외 상황: localStorage를 브라우저가 막아둔 상태(시크릿 모드 등)에서의 동작

## 회귀 테스트가 중요한 기능

* 기능 1: streak 계산 (정책이 바뀌면 가장 먼저 깨진다)
* 기능 2: 날짜 키 생성 (타임존·자정 경계)

## 품질 기준

* 습관 20개 × 14일 격자를 렌더해도 체감 지연이 없어야 한다.

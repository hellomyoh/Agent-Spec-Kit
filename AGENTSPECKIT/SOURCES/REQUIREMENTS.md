# REQUIREMENTS.md — Project Initial Requirements

This document is the **user input document** for Agent-based project initialization. (formerly `AGENTINIT.md`)

The user must fill in the project overview, rough requirements, core features, and constraints in this file, then deliver it to the Agent together with the `KICKOFF.md` prompt.

Based on this document, the Agent analyzes the project and generates the feature specification, user documentation, QA documentation, the development plan, the cross-cutting contract document (`ARCHITECTURE.md`), and the Agent work order.

## Lifecycle Rules for This Document (`KICKOFF.md` 15.2)

This document follows the same lifecycle rules as the other submitted materials in `SOURCES/`.

* Type: **Initial requirements** — one per project. `KICKOFF.md` processes it **once** during initialization, and it is not subject to the change-request procedure used during development (`DEVELOPINIT.md` 4.2).
* While initialization is in progress (status `Under review`), you can **freely edit** it to incorporate answers to the Agent's questions.
* Once initialization is complete, the status becomes `Applied` and from then on this document is **immutable**.
  For additional or changed requirements, do not edit this file; instead submit a **new change-request document** to `SOURCES/` (guide README Section 5.1).
* If you have **reference material** such as external API specs or policy documents, place it in this folder as well.
  It is read together during initialization and registered in `SOURCES/INDEX.md`.

> Important: If the contents of this document are too empty or the core requirements are ambiguous,
> the Agent must not continue initialization but instead ask the user questions to clarify the requirements.

> Writing tip: You do not need to fill in every item perfectly.
> However, write **item 2 (Project Description)**, **item 3 (Core Features)**, **item 4 (User Scenarios)**, and,
> if there is external integration, **item 5** as concretely as possible.
> If these items are empty, the Agent will hold off on initialization and ask questions.

> When adopting into a project that is already under development (brownfield), use `ADOPT.md` instead of `KICKOFF.md`, and
> this `REQUIREMENTS.md` is **optional**. In that case you only need to write "future goals, unimplemented requirements, and constraints" (the current state is reverse-extracted from the code),
> and if you leave it empty, the Agent will create the current-state documents from the code and then ask only as many questions as needed.

# 0. Delegating Items You Don't Know to the AI

For items where you are unsure what to fill in or find hard to decide, instead of leaving them blank,
write the marker below and the Agent will decide on your behalf.

* `[AI-delegated]`  (aliases: `[Delegate to AI]`, `[Unknown]`)

How it is handled depends on the item's risk level.

* **Non-core items** (naming, code style, non-core UI, lower-priority feature details, log format, etc.):
  The Agent picks a reasonable default and proceeds, recording it in `ASSUMPTIONS.md`. It does not ask.
* **Core items** (MVP scope, data model, authentication/authorization, personal-data handling, external integration approach, etc.):
  The Agent does not stop initialization; it adopts **the most conservative, easily reversible choice** as a provisional decision.
  This provisional decision is recorded in `ASSUMPTIONS.md` and is collected and displayed under
  **"Items decided by AI delegation (review recommended)"** in the initialization report, so you can confirm or revise it later.

Caution:

* **If you delegate or leave blank both the project purpose and the core features**, the Agent will not accept the delegation and will ask instead.
  "What this project is" cannot be delegated.
* For items involving **cost, billing, legal impact, or hard-to-reverse behavior**, even if delegated, the Agent will not decide silently;
  it picks a conservative default with no cost/risk and then requests confirmation in the report.

Example:

```text
## Authentication / Session Model (common)

[AI-delegated]   ← The Agent provisionally adopts a conservative default (e.g., standard token-based + secure storage) and shows it in the report

## Design Tone

[Unknown]        ← Non-core, so the Agent picks a default and proceeds, recording it only in ASSUMPTIONS.md
```

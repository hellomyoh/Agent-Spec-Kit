### Implemented so far
- `__init__`: `self._records: list[dict]` (insertion order = append order).
- `add(record)`: stores a **deep copy** (callers may mutate their source after).
- `all()`: returns deep copies of all records, insertion order.
- `query(where=None, sort_by=None, limit=None, offset=0)` FULL pipeline now:
  filter(where) -> sort(sort_by) -> offset -> limit.
  - **`where` (S2):** keeps records matching ALL key==value pairs (AND). A key
    ABSENT from a record FAILS the match (no error). Test is
    `all(k in r and r[k]==v ...)`. Empty/None `where` = no filtering.
    Value-equality (`==`), not identity.
  - **`sort_by` (S4):** ascending by that field's value, `sorted(results,
    key=lambda r: r[sort_by])`. STABLE -> equal keys keep insertion order.
    Applied AFTER filter, BEFORE offset/limit. `sort_by is None` -> no sort
    (baseline insertion order). Distinguish None from a falsy field name.
  - **Pagination (S1/S3/S5):** `offset` skips N leading records of the
    filtered+sorted set; `limit` caps count. **DEFAULT_PAGE_SIZE = 40** when
    `limit is None` (history: 7 in S1 -> 25 in S3 -> 40 in S5). `limit=0`
    returns []. Distinguish `limit is None` (->40) from `limit=0`. Default
    applies to the post-filter+sort result set.

### Key invariants (keep these!)
- **Always return copies** (`copy.deepcopy`) on add and read so internal state
  can't be mutated via inputs or outputs. Records can be nested dicts.
- **Insertion order** is the baseline ordering; `sort_by` ties must keep it
  (stable sort).
- Keep the FIXED signature; never change it across sessions.
- Pipeline order is load-bearing: filter -> sort -> offset -> limit. Sort sits
  between filter and slicing so the default page size pages the sorted set.

# L2 적합성 파일럿 (Conformance Pilot)

프롬프트(Solo 에디션 / Team 에디션)가 **실제로 명세대로 동작하는지**를 에이전트 1회 구동으로 확인하는 파일럿입니다.
합/불 판정은 전부 **git 흔적·파일 존재**로 떨어지게 설계했습니다(주관 판단 최소화) — "git 이력 = 데이터셋" 원칙 기반.

> **이건 킷 메인테이너용 검증 자산입니다.** 사용자 프로젝트에 복사되지 않습니다(`en/`·`ko/` 킷 밖, `tests/` 아래). 따라서 여기서 bash/git을 쓰는 것은 프롬프트-only *런타임* 원칙과 무관합니다.

---

## 무엇을 검증하나 (L2의 위치)

- **L0(정적 무결성)** = 킷이 모순 없이 맞물리나 (실행 X).
- **L1(AUDIT)** = 라이브 프로젝트가 규율대로 도나 (내장).
- **L2(이 문서)** = **프롬프트를 돌리면 의도한 산출물·행위가 나오나** (에이전트 1회 실행 + git 대조).
- **L3(연구 벤치마크)** = 정말 더 나은 결과인가 (연구 — [benchmark/METHODOLOGY.md](../../benchmark/METHODOLOGY.md) 참조).

## 성격과 한계 (정직)

- 에이전트 출력은 **비결정적**입니다. 따라서 이건 unit test가 아니라 **스모크 테스트**입니다 — 매 변경마다가 아니라 **릴리즈 전·프롬프트 큰 변경 후**에 1회 돌립니다.
- 한 번 PASS가 "항상 동작"을 증명하지 않습니다. "지정 시나리오에서 프롬프트가 명세대로 구동됨"을 보일 뿐입니다(프레임워크가 인정한 한계와 동일선).
- **MUST** 체크가 하나라도 FAIL이면 → 프롬프트 결함 후보로 기록하고 수정합니다. **SHOULD**는 권장.

---

## 실행 환경

- 격리된 임시 git 저장소(아래 setup이 만듭니다).
- 에이전트(Claude Code / Codex / Cursor 등) 1개. team 파일럿은 **2개 git identity**를 시뮬합니다(별도 머신 불필요 — `git -c user.email=...` 로 작성자만 바꿈).
- 아래에서 `<REPO>` = 이 저장소(THROUGHLINE) 루트 경로.

## 시드 입력

[`seeds/REQUIREMENTS.md`](seeds/REQUIREMENTS.md) — 작은 URL 단축 서비스(기능 2~3개 + 인증·데이터모델·에러포맷 계약). solo·team 파일럿이 공용으로 씁니다(Korean 킷 기준; en 킷으로 돌리면 시드를 영어로 번역).

## 실행 순서

1. [`solo-pilot.md`](solo-pilot.md) — KICKOFF → DEVELOP → 드리프트 주입 → AUDIT, 단계마다 체크리스트.
2. [`team-pilot.md`](team-pilot.md) — KICKOFF → claim×(겹침/비겹침) → DEVELOP → INTEGRATE → AUDIT, 단계마다 체크리스트.

각 파일럿 끝의 **판정표**에 PASS/FAIL을 기입하면 됩니다. FAIL 항목은 어느 프롬프트의 어느 절이 안 지켜졌는지 함께 적습니다.

## 판정 기준

```text
적합(PASS)   = 모든 MUST 체크 PASS
부적합(FAIL) = MUST 1개 이상 FAIL  →  해당 프롬프트 절을 결함으로 기록·수정 후 재실행
```
